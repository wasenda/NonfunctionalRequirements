# Non-Functional Requirements

Анализ и формализация нефункциональных требований для информационных систем.

Проект посвящён определению требований, характеризующих не только функциональность системы, но и качество её работы: производительность, доступность, надёжность, масштабируемость и безопасность.

## О проекте

В работе рассмотрены два сценария автоматизации:

- система онлайн-записи в сеть барбершопов;
- информационная система для управления доставкой заказов.

Для каждого сценария определены требования, влияющие на эксплуатационные характеристики системы и на способность системы сохранять заданный уровень качества при изменении нагрузки и условий работы.

## Что сделано

### Идентификация нефункциональных требований

Выделены требования, относящиеся к качественным характеристикам системы, и отделены от функциональных требований.

При идентификации учитывались параметры, связанные с:

- временем выполнения операций;
- количеством одновременно работающих пользователей;
- временем восстановления после сбоев;
- допустимой потерей данных;
- сроком хранения информации;
- режимом доступности;
- масштабом внедрения;
- ограничением доступа;
- требованиями к интерфейсу и локализации.

Например, требование сформировать список свободных слотов является функциональным, тогда как ограничение времени его формирования при заданном количестве одновременных пользователей относится к нефункциональным требованиям.

### Классификация НФТ

Сформированные требования распределены по атрибутам качества.

В проекте рассматриваются:

- **Performance** — производительность;
- **Availability** — доступность;
- **Reliability** — надёжность;
- **Scalability** — масштабируемость;
- **Security** — безопасность;
- **Usability** — удобство использования;
- **Localization** — локализация;
- **Compatibility** — совместимость;
- **Durability** — долговечность хранения данных.

Классификация позволяет определить не только само требование, но и ту характеристику системы, которую оно ограничивает или описывает.

## Производительность

Для производительности требования формулировались с учётом двух ключевых параметров:

1. целевого времени выполнения операции;
2. заданной нагрузки.

Такой подход позволяет формулировать измеримые требования, например ограничивать время формирования результата при одновременной работе определённого количества пользователей.

Также учитывается объём обрабатываемых данных и требования к времени выполнения массовых операций.

## Доступность и надёжность

Отдельно определены требования, характеризующие способность системы продолжать работу и восстанавливаться после сбоев.

Рассмотрены:

- допустимое время восстановления;
- допустимый объём потерянных данных;
- режим работы системы;
- технологические перерывы;
- сохранность ранее введённых данных.

Таким образом, доступность рассматривается совместно с надёжностью и возможностью восстановления системы после отказа.

## Масштабируемость

Для оценки масштабируемости использован сценарий поэтапного расширения системы.

Для системы онлайн-записи предусмотрено первоначальное внедрение на ограниченной части сети с последующим расширением на остальные регионы. При формировании требований учитываются рост количества пользователей, мастеров и точек присутствия системы.

Для системы доставки масштабирование рассматривается через увеличение количества заказов, курьеров и операций, выполняемых в системе.

## Безопасность

Определены требования, ограничивающие доступ пользователей к операциям и данным в соответствии с их ролями.

Основные принципы:

- разграничение прав доступа;
- доступ к административным операциям только авторизованным ролям;
- ограничение доступа к данным определённой зоны ответственности;
- запрет выполнения критичных операций пользователями без соответствующих полномочий.

Требования к безопасности рассматриваются как отдельный атрибут качества, а не как часть описания функционального поведения.

## Локализация и удобство использования

Помимо эксплуатационных характеристик, учтены требования к пользовательскому взаимодействию.

Рассмотрены:

- работа с региональным временем;
- локализация интерфейса;
- адаптация интерфейса под пользовательские потребности;
- требования к представлению информации.

Для распределённой системы особенно важно корректно учитывать региональные особенности пользователя и его локальное время.

## Архитектурный контекст

Нефункциональные требования рассматриваются как основа для последующих архитектурных решений.

Производительность, доступность, надёжность, масштабируемость и безопасность непосредственно влияют на:

- выбор архитектуры;
- организацию хранения данных;
- взаимодействие компонентов;
- требования к инфраструктуре;
- методы обработки нагрузки;
- механизмы восстановления;
- модель разграничения доступа.

Поэтому НФТ формируются до реализации системы и используются как ограничения, определяющие техническое решение.

## Артефакты

В проект входят результаты нескольких этапов анализа:

| Артефакт                   | Содержание                                                       |

| Идентификация НФТ          | Выделение предложений, содержащих нефункциональные требования    |
| Классификация НФТ          | Отнесение требований к соответствующим атрибутам качества        |
| Выбор НФТ                  | Определение значимых качественных характеристик для сценария     |
| Performance Attributes     | Формулирование требований к производительности                   |
| Availability & Reliability | Формулирование требований к доступности и восстановлению         |
| Scalability Attributes     | Формулирование требований к масштабированию                      |
| Security Attributes        | Формулирование требований к безопасности и разграничению доступа |

## Используемые подходы

В работе применялись:

- анализ требований;
- декомпозиция требований по атрибутам качества;
- классификация НФТ;
- формулирование измеримых критериев;
- анализ ограничений производительности;
- анализ сценариев отказа и восстановления;
- анализ требований к масштабированию;
- анализ требований к безопасности и доступу;
- separation of functional and non-functional requirements.

## Результат

В результате сформирован набор структурированных нефункциональных требований для двух типов информационных систем.

Требования охватывают ключевые эксплуатационные характеристики системы и могут использоваться как основа для архитектурного проектирования, выбора технических решений и последующей верификации качества системы.
